Hair Color Portfolio

Project Overview

A photography-led portfolio for a personal service business. I built JosephHuckabee.com to present my hair-color work, explain services, and give visitors routes to learn more and make contact. The experience uses the work itself as its primary introduction.

Project type — Personal brand and service portfolio. Work shown — Interface design, responsive layouts, image presentation, and front-end implementation. Technology — HTML, CSS, and vanilla JavaScript, with Netlify form markup and an optional serverless Instagram integration in the source.

The core journey is simple: discover the work, explore the portfolio or service menu, then follow the contact route. Supporting biography and social links give visitors additional context.

Visit the hair-color website

The Problem

For a visual service, visitors need to judge the work before deciding whether to take the next step. A strong photographic presentation still needs understandable navigation and useful service information.

The design challenge was to balance an expressive image-led introduction with practical routes to the full portfolio, biography, services, and contact. Large image files and animated presentation also introduced performance and motion considerations.

These are design requirements evident in the implementation, not findings from a documented customer study. No previous-site usability baseline was available.

Goals & Objectives

Put the work first — Make hair-color photography the dominant content while keeping the business identity and next actions readable.

Make browsing practical — Provide a dedicated gallery, larger image views, a service menu, and a consistent route back to navigation.

Support smaller screens and different access needs — Adapt image sizing, manage motion, provide keyboard-operable interactions, and use explicit form labels.

Keep the portfolio maintainable — Separate page markup, shared styles, and interaction scripts, and retain a static image fallback for the optional social feed.

Research & Discovery

The content inventory consists of original work images, a biography, a service menu, social links, and communication pages. It establishes three intended tasks: evaluate the aesthetic, understand the services, and find a way to get in touch.

I reviewed the site’s pages, shared CSS, carousel and gallery JavaScript, serverless feed code, and Git revisions. The public homepage, portfolio, services, and contact routes also loaded during review.

Design Process

Information architecture — Home, Bio, Portfolio, Services, and Contact provide separate destinations for discovery, background, visual evaluation, service details, and communication. Instagram and TikTok links extend the personal brand beyond the site.

Visual hierarchy — Large photographs introduce the work; concise positioning copy and Contact/View portfolio actions create a next step. The service page groups offerings by name, description, and duration, while a contrasting display style separates headings from body text.

Image browsing — The portfolio grid supports enlarged image views with captions. The implementation responds to click, Enter, and Space, moves focus to the close control, and returns it to the selected image when the viewer closes. A full modal keyboard audit has not been documented.

Motion and performance — The carousel includes pause/resume controls and checks the visitor’s reduced-motion preference. It pauses when the document is hidden. Responsive image variants, explicit dimensions, lazy loading for later images, and prioritized initial images address the demands of a photography-heavy page.

Communication — The current Contact page presents a Hair Notes signup/message form rather than an appointment scheduler. Its fields and button copy establish a communication interface; provider delivery, mailing-list operations, and booking outcomes have not been verified.

Challenges & Iterations

Adjusting the photographic hero — Revision 9ddfb12 changed desktop image widths and focal positioning, introduced intermediate-screen sizing, and aligned the image sizes attribute with the layout. The result is a more explicitly controlled image presentation across breakpoints; no load-time improvement was measured.

Handling mobile viewport space — The same revision moved from a tightly constrained small-screen layout toward dynamic viewport sizing, normal vertical overflow, and safe-area-aware bottom padding. A later revision, fb26d41, adjusted the mobile header grid and expanded the mobile layout breakpoint.

Refining navigation language — Revision 7543183 changed the navigation label from Appointments to Contact and added labeled social-icon links. The label better describes the destination’s current communication role. Other active-navigation details still merit review before claiming the navigation is fully validated.

Keeping a social-feed fallback — The client retains its static image links when the optional Instagram request fails or returns no items. The serverless function also handles a missing access token. This provides a defined fallback without proving that the live integration is configured.

Outcomes & Reflection

Delivered — A live personal-service portfolio that gives the work prominence and organizes biography, gallery, service, and communication content into recognizable destinations.

The project demonstrates the tradeoffs of image-led interaction: photography needs room and visual impact, while motion, image payload, navigation, and communication labels still need deliberate attention.

No booking, signup, conversion, or usability improvement is claimed. A useful next step would be to observe prospective clients moving from an image to service information and contact, and verify the complete form-delivery workflow.
